# Magica Cloth 2 是怎么做的（调研，2026-10-02）

起因：骨骼布料调过一轮之后，用户看了 `out\g04_skirt_fix.mp4` 说"不行，还是有问题"，要先弄清楚 Magica Cloth 2（下称 Magica）本身是怎么实现的，
不再凭感觉调参数。

**结论先说：**

1. Magica 的骨骼布料（BoneCloth）和我们的 `RoeBoneCloth` 底子相同：骨骼当质点，按"基线"逐节做角度恢复、角度限制，加惯性、碰撞、背挡。
   参数的含义也基本一一对应（我们的插件本来就是照它的文档写的）。
2. 之前的猜测**核实了**：Magica 能把相邻的骨链横向连成网（连接方式 Automatic Mesh / Sequential Loop Mesh / Sequential Non Loop Mesh），
   横边上有距离约束、三角形之间有弯曲约束、横边也参加碰撞，一片裙子当一块布来算。我们只有 Line（每条链各自独立）。
   查了模型的蒙皮：**a08 每侧的长裙是一整片布，挂在前、侧、后 3 条链上；g04 的前片是一整片布，挂在 2 条链上**——我们把它们当成互不相干的绳子，
   视频里 g04 的前片下摆折起、卷边，就是两条链各摆各的。
3. 但这不是全部。Magica 文档对裙子的头号建议是**让"动画姿势"跟着腿走**：裙子蒙皮到腿上，或者美术逐个动作调好，模拟只是叠加在上面；
   做不到时用它的 Custom Skinning（把裙子自动蒙皮到指定的腿骨上）。游戏自己的技能动作正是美术手调的裙子。
   而我们动捕动作里的"动画姿势"是站架里的裙子钉在骨盆上：腿每迈一步都插进裙子，全靠碰撞把裙片推开，裙片就像硬板绕着腰转、被腿推着走。
4. 游戏本身**从不模拟裙子**：95 个 Magica 组件全在大厅模型上、全是 Line 模式、同一套头发模板（世界和局部惯性都是 0，质点限速 1 米/秒，非常稳）；
   战斗模型里一个都没有，裙子靠手调动画。所以照搬游戏的 Magica 设置解决不了裙子。
5. 建议：照 Magica 的做法改 `RoeBoneCloth`——裙子的动画姿势跟腿走（用游戏手调的裙子动画来标定）、一片布的几条链横向连起来、惯性分世界和局部。
   买 Magica（$17.50）能省掉第 2 条，但第 1 条照样要做；而且它挂在 Unity 的帧循环上按自己的时钟跑，我们离线录视频、跑检查时是手动一步一步推进的，
   它不会跟着动。详见第 8 节。用户选了 A，并要求可插拔、以后能换成 Magica：已做好，见第 9 节。

## 2. Magica 的结构

- **粒子 + 约束**，直接改位置的那类解法（PBD 式）。用 Unity DOTS（Burst 编译 + Job 多线程）写的，只用 CPU。
  公开的源码分析说积分是半隐式（leapfrog）。
- **固定频率**：默认每秒 90 步，和帧率无关；每帧最多 3 步，超出的跳过，用插值补位置。参数是在 90 Hz 下调的，
  手册说改了频率动作会变，要重调。
- **三种类型**：
  - BoneCloth：骨骼（Transform）就是顶点，模拟完写回骨骼的位置和旋转；
  - MeshCloth：从渲染网格简化出一个"代理网格"来模拟，再按距离权重带动原网格的顶点；
  - BoneSpring：给骨骼加弹簧（胸部）。
- **代理网格**：模拟的对象。BoneCloth 的顶点是骨骼本身：登记的根骨是**固定点**，下面的都是**可动点**。
  边：Line 模式只有父子边；网格模式另加横向边和三角形（见第 3 节）。
- **基线和深度**：从固定点沿着连接走到末端的路径叫基线，BoneCloth 的基线就是骨骼层级。每个顶点有深度（根 0、最远的末端 1）。
  带 [C] 按钮的参数都能用曲线按深度取值，比如角度限制在根部 12°、中间 36°、末端 60°。
  手册的说法是"沿基线恢复形状，得到一种 2.5D 的动作：既有二维动画式的动作，又保留物理感"。
- **两个基准姿势**：
  - 初始姿势：组件创建时记下的姿势；
  - 动画姿势：这一帧不用 Magica 时骨骼（或网格）被动画摆成的姿势。
  - `Animation Pose Ratio`（0–1，默认 0）在两者之间混合，影响角度恢复、角度限制、形状保持三项；**背挡和最大距离永远按动画姿势**。
  - 手册：一般留 0 更稳；动画姿势变形很大，或者"完全由美术控制"时，调高（从 0.5 试起）更稳。
- **写回旋转**（BoneCloth）：每根骨朝向相邻顶点。`Rotational Interpolation` 0 = 朝父、1 = 朝子（多个子取平均）；
  `Root Rotation` 决定固定的根骨朝子骨转多少。末端骨没有子，只能朝父。

### 各项约束

| 项目 | 做什么 | 参照什么 | 参数（取值范围；默认） |
|---|---|---|---|
| 重力、阻尼 | 重力；空气阻力 | — | 重力 0–10 米/秒²（5）；`Gravity Falloff`：布处在初始朝向时重力减弱；阻尼可按深度变（0.05） |
| 角度恢复 Angle Restoration | 每条基线边往原来的角度转回一部分；"最重要的参数，大部分动作由它决定" | 相对父边；基准 = 初始 / 动画姿势按比例混合 | 刚度（每次修正转回多少，可按深度变）；速度衰减（修正的位移有多少不变成速度，越低越像弹簧）；重力方向衰减（布朝上时恢复力减弱，重力为 0 也起作用） |
| 角度限制 Angle Limit | 每条边相对父边最多弯多少 | 同上 | 限制角（度，可按深度变）；刚度（越低越软地弹回） |
| 距离 Distance | 每个顶点和相连顶点保持距离（伸缩） | 原来的边长 | 刚度 0–1（1），可按深度变；手册：转圈的裙子可以把末端放松一点 |
| 系绳 Tether | 顶点离自己基线起点最多缩短多少，防止整片布塌缩 | 原来离起点的距离 | `Compression` 0–1（0 = 不许缩短；2.12 起默认 0.4）；手册建议不低于 0.8，太严动作会僵 |
| 三角弯曲 Triangle Bending | 相邻两个三角形的夹角回到原来的角度 | 原来的夹角 | 刚度 0–1（1）；没有三角形（Line 模式）就不起作用 |
| 惯性 Inertia | 角色的运动有多少传给布 | 见下 | 见下 |
| 最大距离 Max Distance | 顶点离动画姿势的位置不超过一个半径 | 动画姿势 | 半径，可按深度变；刚度 |
| 背挡 Backstop | 动画姿势顶点沿法线反方向的背后放一个球，顶点进不去 | 动画姿势 | 球半径 0.1–10；离顶点的距离（可按深度变）；刚度。BoneCloth 的法线默认是骨骼的 Y 轴，可改成从一个中心向外放射 |
| 碰撞 Collider Collision | 球、胶囊（两端半径可不同）、无限平面 | 碰撞体当前位置 | 模式：点（顶点当小球）/ 边（边当胶囊，不会从小碰撞体旁边漏过去，计算量是点的几倍）；半径可按深度变；摩擦 0–0.5 |
| 自碰撞 Self Collision | 布和自己、和另一块布不互穿（点对三角形 + 边对边） | — | 测试版，很费（文档标十颗星），要有三角形 |

### 惯性

- **三层**：锚点（比如角色站的移动平台，可以整个扣掉）→ 世界惯性 → 局部惯性。
- **世界惯性**：整个角色在世界里的移动和转动，从 MagicaCloth 组件所在的 Transform 量（所以要放在角色根下面）。
  - `World Inertia` 0–1：0.1 表示角色移动的 10% 传给布；
  - `World Movement / Rotation Speed Limit`：超过这个速度（米/秒、度/秒）的部分不再传给布，手册推荐用它而不是 `World Inertia`；
  - `World Inertia Smoothing`（2.12 起默认 0.4）：把角色的移动平滑一下，急起急停不打乱布。
- **局部惯性**：角色内部的动作（动画）对布的影响，从布的"中心"量：中心由固定点的分布自动算出（场景里那个紫色小球）。
  `Local Inertia` 0–1、局部移动 / 转动限速、`Depth Inertia`（靠近根部的顶点动得少，末端不减）。
- **其他**：离心力增强、**质点限速**（每个顶点的最大速度，低于 1 米/秒碰撞会不准）、瞬移检测（超过一定距离 / 角度就重置或保持）。
- 重置后有一段稳定时间（默认 0.1 秒），开始时布和碰撞体重叠也不会被一下子弹开。

## 3. 网格连接：一片布当一块布算（之前的猜测，已核实）

手册 "BoneCloth advanced settings" 原话：BoneCloth 可以从登记的骨骼自动建网格，"骨骼之间的连接更牢，形状保持和碰撞判定都更强；
横向也连成了边，配合边模式碰撞，碰撞还能更强"。手册用一圈 10 条链的裙子举例：

| 连接方式 | 怎么连 |
|---|---|
| Line（默认） | 只有父子边，各条链独立 |
| Automatic Mesh | 自动连附近的骨骼；骨骼排得不规则时形状可能不自然 |
| Sequential Loop Mesh | 按登记根骨的顺序横向连，首尾连成一圈（整圈的裙子） |
| Sequential Non Loop Mesh | 同上，首尾不连 |

连成网以后：横边有距离约束，三角形之间有弯曲约束，边模式碰撞把横边也算进去，还能开自碰撞。
一篇日文心得说得很直白：Line 模式左右不相连，腿会从链和链的缝里穿出去；换成 Automatic Mesh 腿就进不去了。

**我们的模型**（`magica_survey.py links`，看有没有三角面跨在两条链上）：

| 角色 | 一片布挂在几条链上 | 跨链三角面 / 两边都有权重的顶点 |
|---|---|---|
| a08 | 每侧长裙：前片 `Skirt_L_08` – 侧片 `Skirt_L_01` – 后片 `Skirt_L_16`（右侧是 `R_16`、`R_01`、`R_08`） | 80 + 20 / 260 + 245 |
| a08 | 后腰两条短片 `Skirt_M_00` – `Skirt_M_01` | 6 / 129 |
| g04 | 前片 `Skirt_front_007` – `Skirt_front_01` | 50 / 181 |
| g04 | 后片 `Skirt_Back`（宽约 26 厘米）、左侧长飘带 `Skirt_Left`（约 21 厘米）、装饰条 `Skirt_dec_Line`：各自一条链 | — |

图：`out\skirt_sheets_1002.png`（颜色 = 顶点挂在哪条链上，虚线 = 建议加的横向连接）。

g04 的后片和飘带各只有一条链，宽度方向本来就是一整块转，游戏里也一样；要它们在宽度方向弯，得像 MeshCloth 那样另建代理网格，游戏自己也没这样做，不需要。

## 4. 游戏自己怎么用 Magica

`magica_survey.py settings`：264 个大厅模型包里 95 个 MagicaCloth 组件，**全是 BoneCloth、全是 Line、几乎同一套参数**：

| 参数 | 游戏的值（95 个组件） |
|---|---|
| 重力、阻尼 | 5、0.05（全部） |
| 质点半径 | 1.5 厘米（68 个），其余 0.6–9 厘米 |
| 角度恢复 | 刚度 0（73 个）或 0.2（22 个），速度衰减 0.8 |
| 角度限制 | 90° × 深度曲线（根 0°、梢 90°）为主，少数 5° / 15° |
| 世界 / 局部惯性 | 0 / 0（全部） |
| 质点限速 | 1 米/秒（全部） |
| Tether、距离刚度 | 0、1 |
| 碰撞 | 点模式；没开背挡和最大距离 |
| 动画姿势比例 | 0 |
| 旋转 | 朝子骨 1、根骨旋转 1 |

- 模拟的是头发、刘海、耳饰、缎带、锁链；像布的只有几件：a08 裙上的两条锁链、a12 裙子两侧的两条链、几件头纱、披肩、k06 的斗篷。
- 战斗模型包（`chara_armor_*_hd & ld_hd.ab` 和 `_ld*.ab`）里没有 Magica 组件（抽查 a08、g04、a12、k06）：**战斗里全部是手调动画**，裙子也是
  （a08 以前在 ripper_tpose 的调研里查过，见那边的 `docs/bone-cloth-guide.md`）。
- 这套参数让头发几乎不受角色移动影响（惯性 0、限速 1 米/秒），大厅里很安静；拿来做格斗里的裙子没有参考价值。

## 5. 和 `RoeBoneCloth` 逐项对比

| 项目 | Magica Cloth 2 | RoeBoneCloth（现在） |
|---|---|---|
| 步长 | 固定 90 Hz，每帧最多 3 步，跳过的插值补 | 每步 1/60 秒拆成 2 个子步（120 Hz）；刚度按 90 Hz 换算 |
| 顶点 | 骨骼本身，根骨固定 | 每根骨的尾端（最后一节的尾端按蒙皮估） |
| 连接 | Line 或三种网格 | 只有 Line |
| 骨长 | 距离约束，可按深度放松 | 刚性，每次修正后投回骨长 |
| 横向距离、三角弯曲 | 网格模式有 | **没有** |
| Tether | 有 | **没有**（链可以往根部对折） |
| 角度恢复 | 相对父边；基准按比例混合初始 / 动画姿势；刚度曲线、速度衰减、重力方向衰减 | 相对父边；基准 = 动画姿势；刚度、速度衰减；每子步一次 |
| 角度限制 | 同上基准；按深度曲线；软限制（刚度） | 根到梢线性插值；硬限制 |
| 惯性 | 世界（角色根，平滑、限速）+ 局部（布的中心，深度惯性）+ 离心力 + 质点限速 + 瞬移检测 | 挂点骨（裙子是骨盆）一个比例 + 移动 / 转动限速 + 质点限速；世界移动和动画混在一起 |
| 碰撞 | 点 / 边（网格模式下横边也算）；半径按深度；摩擦 | 边模式（只有骨段）；动画本身压进碰撞体的深度放过；推开的位移九成不变成速度；杠杆和单次推量有上限 |
| 背挡 | 动画姿势顶点沿法线反方向的球 | 有，法线 = 从身体轴水平向外 |
| 最大距离 | 有 | 没有（插件里有，没移植） |
| 动画姿势 | 美术蒙皮或逐个动作调；或 Custom Skinning | 游戏动作：手调关键帧（不模拟）；动捕动作：站架的裙子跟着骨盆转，**不跟腿** |
| 重置后稳定 | 0.1 秒 | 没有 |
| 自碰撞 | 有（测试版） | 没有 |
| 写回旋转 | 朝父 / 朝子插值，根骨也转 | 动画朝向随父骨的偏转转过去，再摆到模拟方向（保留动画的扭转） |
| 地面 | 平面碰撞体 | 有 |

## 6. 为什么还不自然

对着 `out\g04_skirt_fix.mp4` 修改后那一半逐帧看（前进 2.0–2.4 秒、直拳 8.0–8.4 秒、回旋踢 9.6–10 秒）：

1. **一片布被拆成几根绳子**：g04 前片的两条链各摆各的，下摆折起、往一边卷；腿也能从两条链之间穿过去。a08 每侧三条链同理。
   → Magica 的网格连接正是解决这个的。
2. **动画姿势不跟腿**：动捕动作里，裙子的基准是站架里的样子钉在骨盆上（`FighterRig` 的根骨修正只让它跟骨盆、胯部朝向转）。
   迈步、踢腿时腿整个插进这个基准里，模拟只能靠碰撞往外推：裙片像硬板绕着腰转，被腿推着走，推完又被角度恢复拉回腿里。
   游戏手调的裙子是跟着腿走的：`RoeHelperFit.SkirtReport` 量过，g04 前片、侧片的根骨"钉在骨盆上"离游戏关键帧 27–28°，
   最好的"骨盆和大腿之间混合"也还差 20–23°（游戏的裙子本身摆幅 35–47°，大部分是摆动，靠模拟补）。
   → Magica 的答案是让动画姿势跟腿（美术蒙皮或 Custom Skinning），模拟叠加在上面，背挡、最大距离都相对这个姿势。
3. **惯性没分世界和局部**：前冲、后退、被击退时整个角色的移动和摆胯、迈腿算在同一个比例里，前后移动也会把裙子甩起来。
4. **没有 Tether**：链可以往根部对折（g04 前片卷边的另一半原因）。

## 7. 不用照搬的

- 游戏的头发模板（惯性 0、限速 1 米/秒）：大厅里安静是对的，格斗里裙子会像钉死的。
- 自碰撞：测试版、很费，我们的裙片之间很少互穿。
- MeshCloth：游戏自己的裙片就是一片一条链。
- 90 Hz：我们 120 Hz 子步、刚度按 90 Hz 换算，等价。

## 8. 改法建议（用户选了 A，做法见第 9 节）

**方案 A（推荐）：照 Magica 的做法改 `RoeBoneCloth`**，按影响从大到小：

**5. 自然下垂（10-03）**：用户："能自然下垂么，还是有一点翘"。
- 第 1 条的基准姿势是"游戏站姿里的裙子被腿带着走"。游戏站姿前倾、屁股往后翘，美术把裙子摆得顺着那个身体斜挂；

  游戏站姿本身 a08 20°、g04 16°；动捕里 a08 19–23°、g04 17–19°。这就是"还有一点翘"。
- 改法：`RoeSkirtRig.Drape`（默认 1，F5 切换），基准姿势改成"挂在身体上自然下垂"：
  - 身体表面 `RoeBodySurface`：胯到脚的皮肤点（胯部只取 `*_skin` 材质，腿上任何材质，含护甲和鞋），2.5 厘米一个，只留法线朝外（离腿的轴线、躯干的竖轴）的点，
    每步按骨骼线性蒙皮。离皮肤的有符号距离 = 附近点切平面距离的高斯加权平均（σ 2 厘米），再加一点"远在外面"的权重，附近只剩几个远点时平滑地变成"不碰"。
    第一版用"最近一个点"，腿在旁边动时最近点换来换去，基准姿势一步跳 40–90°。
  - 每节骨：从上一步的方向往竖直落（`DrapeSettle` 0.05 秒），中线和中点离皮肤至少 `DrapeClearance`（1.2 厘米）+ 这节布的厚度（顶点到骨线、沿布面法线的 98% 分位，最多 4 厘米）；
    只算朝本链那一侧（`DrapeFacing` 0.2）或朝上的皮肤。贴近皮肤的平布绕骨转到和皮肤相切（`DrapeTwist`）。

## 10. 装上真的 Magica Cloth 2（10-04 晚）

用户："magic cloth2 下载到E:\Downloads\布料模拟插件 Magica Cloth 2 了，看看能不能用"；接着："之前riseoferos的布料都不完美，尽量修正一个，

**结论：能用，两个游戏的骨骼和衣服都能接上。** ROE 的 a08（Inase）两片长裙和后腰垂片交给 Magica 的 **MeshCloth**（直接模拟裙子网格），
看起来是真的布：踢腿时裙片搭在抬起的腿上、有褶皱，不再像木板一样跟着腿飞出去或直直地垂着。
DOA6 的霞（海盗裙 `kas011`）的网格布用 **BoneCloth** 模拟控制点，看得见的布照旧每帧从控制点重建。F4 的 `magica` 方案。

### 装法

- 插件包 `E:\Downloads\布料模拟插件 Magica Cloth 2\Magica Cloth 2 v2.18.2.unitypackage`（只读，没改 Downloads）解到 `Assets/MagicaCloth2`，
  示例场景没解。这个目录在 `.gitignore` 里，**不进仓库**（付费插件）。依赖的 Burst、Collections、Mathematics 工程里本来就有。
- 插件一加载就自己往 `ProjectSettings/ProjectSettings.asset` 写编译符号 `MAGICACLOTH2`。**这个文件不提交**：没装插件的克隆带着这个符号会编译不过。
  我们的代码全在 `#if MAGICACLOTH2` 里，没装插件时 F4 里就没有 `magica`。以前计划的 `ROE_MAGICA` 不要了。
- 查装好没有：`.\tools\unity_batch.ps1 -Method RoeFighter.EditorTools.RoeMagicaSetup.Check`。

### 怎么接（`Runtime/RoeMagicaCloth.cs`）

- 用我们自己的骨骼布料（`RoeBoneCloth`）找出的分片和量出的腿、胯、躯干胶囊，在运行时搭 Magica 组件（`BuildAndRun`），放在角色根节点下
  （不放进骨骼树：下一个方案按骨骼名字找链，延迟销毁的组件名里带 "skirt" 会被当成裙链）。胶囊变成 `MagicaCapsuleCollider`。
- **BoneCloth**：每个分片一个。横向连成一片的链用 Sequential Non Loop Mesh，成环的（DOA6 的裙子、袖子）用 Sequential Loop Mesh，单链用 Line。
  参数照我们的骨骼布料换算（第 9 节），`animationPoseRatio` 1：往动画（含 `RoeSkirtRig` 跟腿走）给的姿势复原。
- **MeshCloth**：衣服里本身是一块独立网格的布片——爆衣（`RoeClothesBurst`）早就把能脱的部件拆成了各自的 SkinnedMeshRenderer，网格可读——
  直接交给 Magica 模拟网格：a08 的两片长裙和后腰垂片，g04 的前片、左飘带、后片。
  - 哪些顶点固定、哪些动：不用画权重贴图，用 Magica 的运行时接口 `vertexAttributeList` 逐顶点给。顶点权重里挂在这片布的骨链上的至少一半就动，
    否则（挂在胯甲、骨盆上）固定。这几条链于是不再做 BoneCloth，`RoeSkirtRig` 照旧摆它们，就是 MeshCloth 的动画姿势。
  - 写回网格时法线、切线一起写（布料的法线贴图跟着转）。
- 霞的网格布：Magica 每步算完（`MagicaManager.OnPostSimulation`）再按控制点重建看得见的布。
- DOA6 角色的胸不给 Magica（`RoeMagicaCloth.Covers`，交给骨骼布料）：软体格子的约 130 个节点直接挂在胸的枢轴下，
  BoneCloth 会把根骨下面所有物体都收进来，而一个物体最多 127 个子物体（`RenderSetupData`），霞的两个胸组件建不起来。
- Magica 只在播放模式里跑（它挂在 Unity 的帧循环上，自己的 90 Hz 时钟）。编辑器里一步一步推进的检查、静帧、录像看不到它，
  所以另写了播放模式录像 `Editor/RoeClothPlayDemo.cs`（下面）。游戏、exe 里都是播放模式，正常。

### 踩到的坑（每个都改了）

1. **胶囊方向反了**：Magica 的胶囊不居中对齐时，从物体位置**沿轴的负方向**伸出，长度还**包括两头的半球**
   （`ColliderManager`：终点 = 位置 − 方向 × (长度 − 两个半径)）。第一版照手册的字面意思放：大腿胶囊从髋关节往上伸进肚子，还短两个半径——
   腿等于没有碰撞体，第一版视频 `out\mc2_compare_v1.mp4` 里裙子被腿"推开"其实是 `RoeSkirtRig` 的动画姿势。
   改成反向（`reverseDirection`）、长度加上两个半径后，MeshCloth 陷进腿里的顶点 2.7% → 0.8%（再调参后 0.3%）。
2. **布的静止形状取自搭建那一刻的姿势**：Magica 在 `BuildAndRun` 里当场读骨骼姿势，距离、弯曲的静止值、网格简化都按那个姿势算。
   那时角色在战斗站姿里（上一回合没被站姿动画覆盖的骨还停在上一回合的样子），都不是布本来的形状。
   现在搭 MeshCloth 时先把它的骨骼摆到绑定姿势（模型原本的样子），搭完再摆回去（`InBindPose`）。
   所以 `animationPoseRatio` 要保持 1：小于 1 时 Magica 会把骨骼往这个姿势拉。
3. **同一个网格的数据会被下一个组件接手**：Magica 每个渲染器只存一份数据。换方案时旧组件用 `Destroy` 删，要到这一帧结束才真的删掉，
   同一帧新搭的 MeshCloth 就接手了旧的那份（按旧组件搭建时的姿势算的）。同一套参数，前一个镜头是不是 MeshCloth，平均拉伸就是 5% 或 9.5%。
   现在用 `DestroyImmediate` 当场删。
4. **DOA6 的网格是厘米单位、缩放 0.01**：`BakeMesh(…, true)` 烘出的是渲染器自己空间里的坐标，要用它完整的变换矩阵转到世界；
   我们好几处只用了位置和旋转（ROE 模型缩放是 1，没出过问题），在霞身上读出来的皮肤全在 100 倍远的地方：
   身体表面（`RoeBodySurface`）一个点都没有，骨骼布料量腿粗也全退回默认值。改了之后 kas011 的大腿胶囊半径 8.0 / 7.4 厘米（之前默认 7 / 5），
   kas 的 12 / 11.5 厘米（她的服装把量出来的腿撑粗了；默认方案 `auto` 用 DOA6 自己的碰撞体，不受影响）。
5. Magica 在后台搭建，要几帧才开始跑：录像等它跑起来（`RoeMagicaCloth.Ready`）再开拍，搭建失败的写进日志（`Failures`）。

### 播放模式录像和量法（`Editor/RoeClothPlayDemo.cs`）

```powershell
# 录像（要 Unity Hub 开着）；-roeView backright 从右后方拍胯部；-roeNoFrames 只量不拍
.\tools\unity_batch.ps1 -NoQuit -Graphics -Method RoeFighter.EditorTools.RoeClothPlayDemo.Run -Extra '-roeChars','a08,kas011','-roeCloths','magica,magica_style,doa6,off','-roeOut','E:\code\othercode\roe_fighter_unity\_work\mc2_final_front'
python tools\cloth_demo_video.py _work\mc2_final_front out\x.mp4 --chars a08 --variants magica,magica_style,off
# 试 MeshCloth 参数：冒号后面写 RoeMagicaCloth.MeshSettings 的字段（分号隔开），镜头按参数命名；nohip = 裙子不跟腿走
.\tools\unity_batch.ps1 -NoQuit -Graphics -Method RoeFighter.EditorTools.RoeClothPlayDemo.Run -Extra '-roeChars','a08','-roeCloths','magica,magica:limit=60;restore=0.2,off','-roeNoFrames','-roeOut','E:\code\othercode\roe_fighter_unity\_work\mc2_tune'
```

- 批处理进入播放模式（任务存在 SessionState 里，跨过脚本重载），关掉比赛自己的 Update，往 Unity 的帧循环里插两步：Update 之后推进一步比赛，
  PostLateUpdate 开头（Magica 写完之后）拍照。`Time.captureFramerate` 60，每帧正好 1/60 秒，Magica 也按这个走。拍完退出播放模式、关编辑器。
- 每个镜头每一步都量一遍布（`Meter`，不管谁在动它，量法都一样；写进日志和 `metrics.txt`，按脚本的段落分）：
  - **陷进身体**：布的顶点在皮肤（`RoeBodySurface`：胯、腿的皮肤和腿上穿戴的东西）里面超过 1 厘米的比例；
  - **顿挫**：顶点在胯部坐标里的二阶差分 |p − 2p′ + p″|（毫米/步），摆得顺就小，抖和突然一跳就大；
  - **拉伸**：网格的边（3 毫米以上）比模型原本的长度长了多少（平均；最差的取每步第 99 百分位）；DOA6 的重建布和镜头开始时比；
  - **离动画多远、翻过去多少**：只量 MeshCloth——另外挂一个看不见的复制品在同样的骨骼上烘出"动画给的样子"（也就是"关"的样子），
    比顶点平均差多少厘米、多少三角形朝向反过来（布翻过去、拧起来）。骨骼方案动的就是这些骨，这两项量不了。

### 调参：从 Magica 自带的裙子预设开始

Magica 的裙子预设（`MC2_Preset_Skirt.json`）像一块轻薄的丝：a08 踢腿时裙片鼓成帆、绕着腿缠，转身时下摆拧成一股。一步一步往重布料调
（a08，全段平均；陷进 / 顿挫 / 拉伸 / 离动画 / 翻过去）：

| 参数 | 陷进 % | 顿挫 mm | 拉伸 % | 离动画 cm | 翻过去 % |
|---|---|---|---|---|---|
| 起点：Magica 的裙子预设（胶囊已修好；网格简化 3%，角度复原全程 0.2） | 0.8 | 5.8 | 10.8 | | |
| 末端的距离和根部一样硬（预设末端减半）、胶囊碰边不只碰点、阻尼 0.2 | 0.8 | 5.7 | 10.1 | 6.8 | 3.0 |
| + 角度复原 0.4 → 0.2（预设 0.2 → 0.04）、角度限制 35°（预设 60°） | 0.6 | 5.8 | 9.9 | 6.0 | 2.2 |
| + 重力 9.8（预设 5）、世界和局部惯性减半、去掉离心力 | 0.8 | 6.0 | 9.8 | 5.4 | 2.2 |
| + 质点半径 3 厘米（预设 2）、网格简化 4.5% | 0.4 | 6.1 | 7.2 | 5.3 | 1.7 |

- 网格简化（Magica 把渲染网格合并成几厘米一个点的代理网格再算）越细，拉伸、翻过去越多：不简化时拉伸 12%、翻过去 5.8%；
  模拟频率提到 150 Hz 几乎没变化。拉伸最厉害的边在裙片上端、胯甲和链子各占一半权重的地方。
- 默认值都在 `RoeMagicaCloth.MeshSettings` 里，每一项注明了预设原来是多少；`RoeMagicaCloth.Tuning` 可以整体覆盖（录像的 `magica:` 后缀用的就是它）。

### 还没做 / 限制

- 不是默认方案：F4 的 `auto` 照旧（ROE 角色用骨骼布料、DOA6 角色用 DOA6 的）。Magica 不在仓库里，没装插件的克隆没有这个方案；
  它只在播放模式里跑，编辑器里的检查、静帧照旧用我们的解算器。要不要把装了插件时的默认换成它，等用户看了视频再定。
- MeshCloth 的顿挫比骨骼布料大，最差一步（第 99 百分位的边）还会拉长到 2–3 倍，在裙片上端。
  自碰撞试过（`selfCollision=1`）：翻过去 3.0% → 2.1%，其余几乎不变，不如把布调重，没默认开。
- 只有爆衣拆出来的布片能做 MeshCloth（a08、g04）；没拆的（b10、g05 的飘带）和 DOA6 的网格布还是 BoneCloth。
