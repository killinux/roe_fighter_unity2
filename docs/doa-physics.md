# DOA 的胸、头发、衣服物理，和这里的可插拔物理（2026-10-04）

用户 10-04：

- "doa6中的 Kasumi也加入一个角色，看看乳摇，头发，衣服物理是怎么做的，是否比目前的物理做得更好"
- "doa5lr 也调研一下，乳摇，头发，衣服的物理，看物理系统是否有其他差别，最好做成可插拔的设计，后续我买到magic cloth也能替换"

数据都是从本机装的两个游戏里读出来的（只读，不入库）。读数据的脚本在 ripper_tpose 仓库：

- `scripts/doa6/g1m_physics.py`：DOA6 的 G1M（G1MS、NUNO、NUNV、SOFT、COLL）和旁边的 `.swg`、`.rigbin`；
- `scripts/doa5lr/tmc_physics.py`：DOA5LR 的 TMC（ACSCLS、cpf/nodecp 自定义参数）、`.PHYD`，以及 exe 数据段里的胸部预设表。

格式细节在 ripper_tpose `docs/doa-clothing-and-cloth.md`。

下文的可信度这样标：

- **核实**：和几何、骨架对上了数；
- **很可能**：结构或统计上的强证据；
- **猜**：说得通，但没有证据。

## 先说结论

- **DOA6 的胸比我们的丰富。**
  - 它是一块体积软体：约 3 厘米一格的立体格子，每个格点有自己的弹簧目标。
  - 外面一层闭合的壳保持体积，手臂、手、大腿的胶囊能顶进去，网格按格子插值，再在贴身的地方渐变回普通蒙皮。
  - 我们（ROE 角色、霞在"骨骼布料"方案里）是整块胸绕胸壁上的一个点甩，不会被挤扁，也不会保持体积。
- **DOA6 的头发、飘带和我们是同一类。**
  - 都是一根骨头一个质点的骨链。
  - 区别在参数：DOA6 每根链多一个"往动画姿势拉回"的量（0.2–0.5），所以飘带、马尾比我们的安静，不容易乱飞。
- **DOA6 的裙子、袖子更先进。** 它们是粗的控制点网格，看得见的布每帧从 4×4 个控制点插值出来，再沿法线加厚度。
  霞的默认服装没有这种布，她的海盗裙（COS_011）有。10-04 把这套衣服做成第二个霞（`kas011`），网格布照游戏的公式跑起来了（第 10 节）。
- **但"照着它的数据跑"不等于"和游戏里一样好"。**
  - 软体的参数（刚度 270、阻尼 0.75、重力 −6、每轴 10/16/8）是什么意思，数据本身定不了，都是猜的。
  - 照现在的读法：
    - 站着、走路、普通出招时晃得自然：节点平均偏 0.4–2 厘米；
    - 猛的动作（侧踢起手）会把胸整体甩起 6–9 厘米；
    - 罩杯和下面不在软体里的胸衣之间会裂出一条细缝。
  - 要说它"比我们好"，还差在游戏里实拍同一个动作来对照。
- **DOA5LR 的胸没有模拟。**
  - 每边 7 根骨头，按每套衣服选的预设驱动：摆动 0–4 号、变形 0–3 号，表写死在 exe 里，再加每根环骨的振动权重。
  - 衣服、头发是"一个质点就是一根骨头"的弹簧网，和我们的骨骼布料最像，只是弹簧更全：
    - 本田的裙子 19×8 = 152 根骨、997 根弹簧；
    - 有竖向、横向成环、隔一根的横向、隔一根的竖向，加两种斜拉。
  - 刘海是 7 个烘好的姿势按头的运动混合。
- **可插拔**：F4 在几套"物理方案"之间切换。每套方案给胸、身体、头发、裙子、飘带、链子这六类各指定一个解算器：
  - 我们的骨骼布料、10-02 的旧版、DOA6 的、Magica Cloth 2（装上插件后）；
  - 解算器在某个角色身上做不了的类别，自动交给骨骼布料。

  默认方案 `auto`：每人用自己游戏的，霞用 DOA6 的，ROE 角色用骨骼布料。买了 Magica Cloth 2 之后见第 4 节。

## 1. DOA6 是怎么做的（霞：默认服装 `KAS_COS_001` + 头发 `KAS_HAIR_001`）

| 部位 | DOA6 的系统 | 霞 |
|---|---|---|
| 胸（某些衣服还有臀） | 格子软体 `SOFT` | 两边各 188 个格点 |
| 马尾、飘带、绳子 | 骨链 `NUNO4` | 马尾 3 条（12/12/10 根骨，35–55 厘米）；腰后 4 条飘带（各 12 根，61–67 厘米）、右侧 2 条绳（13、19 根） |
| 刘海、鬓角 | 摆动骨 `.swg` | 5 缕 × 2 根 |
| 裙子、袖子、前片 | 粗网格布 `NUNO3` | 默认服装没有；`COS_011` 有：裙子是 20×10 的一圈，两只袖子 10×4，胸前一片 2×6 |
| 骑在胸上的骨头 | `SOFT` 里的 `0x80002` 表 | 565、566 两根（乳沟处，左右胸各一半） |
| 碰撞体 | `COLL`：胶囊（类型 5）和椭球（类型 6），按块分组 | 服装 4 组（19/12/12/12 个），头发 1 组 |
| 辅助骨 | 骨架脚本（`.rigbin` + 编译过的姿势脚本），动作片段不管它们 | 22 根 `RF_*`：上臂、大腿的扭转链和几根不扭转骨 |

### 胸：格子软体

- 格点排成规则的立体格子（核实，拟合误差 2e-6 厘米）：7×7×6 格，间距 2.75 × 3.29 × 2.60 厘米，294 格里有 188 格有点。
- 每个格点按骨骼蒙皮，权重之和是 1（核实），给出它的"动画目标"：
  - 大多数挂在胸骨（10 号）上；
  - 少数挂在脊椎、颈、头、锁骨、上臂的三根扭转辅助骨（`RF_L_Arm_00/01/02`）和 565/566 上。
- 标志位：
  - `0x40` 表面点、`0x20` 内部点（核实：数缺了几个邻居）；
  - `0x01` 在胸壁那一层和最外沿（猜：钉住，跟着目标不动），霞每边 24 个。
- `w_self`：多数是 1，乳沟内侧中段 0.59–0.99（核实位置）。
  - 原来猜是"模拟占多少"，我们先当刚度乘数试过（效果不明显）；
  - 现在当成"这个点显示出多少自己的晃动"（猜），能减少两边在乳沟处互相穿插。
- 壳：表面点上一圈闭合的三角形（82 个，欧拉示性数 2），体积 3.2 升（包住整个格子，比看得见的胸大一圈）。猜：用来保持体积。
- 网格：看得见的胸（霞每边三块：外衣、内衬、皮肤）每个顶点落在一个格子里，用这格 8 个点的三线性权重插值（核实，最大误差 0.11 厘米）。
  每个顶点还有一个值（`Sample0`）：胸前最凸处是 0，贴着身体的边是 1，猜：按它渐变回普通蒙皮。
- 头部 24 个参数，只有几个有名字，含义都是猜的：
  - 重力 −6（臀是 −9.8，所以猜胸是减了的重力）；
  - 阻尼 0.75、刚度 270、一个 1.4；
  - 每轴 10、16、8；
  - 四组系数 0.88、0.55、0.4、0.9；
  - 一个单位向量（−0.087, 0.866, 0.492），前倾 30° 的"上"；
  - 还有 0.35、0.15、0.3 不知道是什么。
- 碰撞：胸只碰它那一组：大腿、小腿、上臂、前臂、扁平的手掌片。
- 565/566 两根骨每帧按两边胸上各一个格子的 8 个点插值摆放（核实），衣服上骑在胸上的部分（COS_011 的胸前片）挂在它们上面。

### 马尾、飘带、绳子：骨链（`NUNO4`）

- 每根骨头一个质点，第一个点钉在父骨上（霞的飘带挂在臀，马尾挂在头）。点的位置就是骨头的静止位置（核实，误差 5e-6 厘米）。
- 游戏里这些骨头在骨架里是平铺的兄弟（马尾 1180–1213 都直接挂在头上），链只在物理数据里。
- 17 个参数（222 条链的统计，名字是猜的）：p0 重力或质量（1–4），p2 阻尼（0.75–1），p3 第二阻尼（0.8–0.98），
  p4–p6 像刚度（0.05–1），p7 永远是 10（迭代次数？），p8 往静止姿势拉回（0.1–1），p9 摩擦（0.8）。
- 霞：
  - 飘带 `1, 0, 0.95, 0.8/0.9, 0.2, 0.2, 0.2, 10, 0.2/0.5, 0.8`；
  - 马尾 `1, 1, 0.75, 0.98, 0.1, 0.2, 0.2, 10, 0.2, 0.8`；
  - 最长那条马尾是 0.9 / 0.96，拉回 0.25。

### 刘海、鬓角：摆动骨（`.swg`）

- 每根骨 15 个浮点：
  - f0–f3 是 0–90 的角度（猜：四个方向的角度限制）；
  - f13 多数是 0.8（猜：阻尼）。
- 霞 5 缕，每缕 2 根，限制如 (15, 0, 17, 17)、(20, 3, 20, 20)。

### 碰撞体（`COLL`）

- 胶囊：a 半径，b 沿本地 Y 的半长（很可能）。c 在布料组里多是 50（无用），在软体组里接近 a：
  - 大腿 (5.87, 10.4, 7.14)；
  - 前臂 (2.45, 8.2, 4.14)；
  - 手掌片 (1.86 或 3.04, 1.04, 0.13)。

  猜：c 是本地 Z 方向的半径（椭圆截面）。
- 每条链、每块软体只碰自己列出的几组。头发的第 0 组只有颈和头。
  服装的第 0 组是给头发碰的身体（统计上的强暗示），所以头发也加上它。

### 辅助骨（`RF_*`）

- 动作片段只动 1–61 号骨（57 根），`RF_L_Arm_00/01/02`（肩、上臂中段、肘）这类辅助骨由游戏的骨架脚本驱动。
- 霞的骨架里有：
  - 上臂、大腿的三节扭转链；
  - 前臂两节；
  - 肘、膝、胯的修形骨；
  - 七对 `*NoTwist`。

## 2. DOA5LR 是怎么做的（霞：`KASUMI_COS_001`）

| 部位 | DOA5LR 的系统 |
|---|---|
| 胸 | 不模拟。每边 7 根骨：胸壁上的 `_base`、往前 8.7 厘米的 `_tip`，`_tip` 后面半圈 5 根环骨（只盖胸的上半）。都在身体网格的蒙皮里，就是普通蒙皮 |
| 胸怎么动 | 每套衣服的自定义参数选预设：`BUST_SWING_PRESET` 0–4、`BUST_HENKEI_PRESET`（変形）0–3、`BUST_PRESS_ENABLE`（猜：挤压），每根环骨一个 `BUST_VIBRATION` 0–0.8。预设表在 exe 的数据段里（5×17、5×17、4×19、4×23、4×23 个浮点）。PC 版选项"关 / Natural / DOA / OMG"对应一张 0、1.0、1.25、1.5、1.75 的倍数表（猜） |
| 衣服、绳子、头发 | `ACSCLS`：一个质点就是一根骨头，骨头之间是弹簧（静止长度、两端分担的比例、拉伸 / 压缩两个刚度）。网格布有竖向、横向成环、隔一根横向、隔一根竖向、两种斜拉；绳子和头发是相邻 + 隔一根 |
| 刘海 | `AcsMixer`：22 根骨，7 套烘好的姿势（静止、左右倾、前后推），按头的运动混合（很可能） |
| 碰撞体 | 每个部件（衣服、头发）一张表：胶囊、椭球、盒子挂在骨头上，加一个地面盒。每条绳、每块布按名字的哈希挑自己碰哪些，可以跨部件（头发碰衣服定义的头饰） |
| `.PHYD` | 刚体（身体体积、能打掉的饰物），不是布料用的 |

- 霞的胸：摆动 1 号、变形 1 号、没有挤压，振动 L1/R1 0.3、L2/R2 0.5。
- 霞的默认衣服：
  - 6 条绳和飘带（11–19 个质点，0.3–0.62 米）；
  - 只碰一个所有衣服都有的"万能"臀部胶囊（半径 25 厘米，不可能是实体，猜：粗筛用的范围），实际上不碰身体。
- 霞的头发：
  - 17 缕，每缕 8–10 个质点；
  - 靠根部的点有一个往动画姿势拉的权重（1、1、1、0.5、0…），等于头皮把根部按住；
  - 刘海走姿势混合。
- 游戏代码段是 SteamStub 加密的，没有动；参数的含义靠数据统计推断。

## 3. 三家对比

| | 我们（RoeBoneCloth，照 Magica Cloth 2） | DOA6 | DOA5LR |
|---|---|---|---|
| 胸 | 胸骨一节一节甩（ROE 角色）；霞在这一方案里是整块胸绕胸壁上的一个点甩 | 体积软体：188 点格子 + 壳 + 碰撞，网格按格子插值 | 不模拟，按预设表程序化驱动 7 根骨 |
| 头发 | 骨链，按名字找 | 骨链（马尾）+ 摆动骨（小缕） | 骨链（每缕 8–10 点）+ 刘海姿势混合 |
| 飘带、绳 | 骨链 | 骨链，多一个"拉回动画姿势"的量 | 骨链（相邻 + 隔一根的弹簧） |
| 裙子 | 骨链连成网（横向连杆）+ 裙子先跟腿走（RoeSkirtRig） | 粗控制点网格，看得见的布插值 + 厚度 | 骨头网格 + 全套弹簧（横环、斜拉、隔一根） |
| 碰撞体 | 量出来的腿、胯、躯干胶囊 | 每块布、每条链、每块软体各有一组 | 每个部件一张表，按名字挑 |
| 参数 | 每类一组，可调 | 每条链、每块软体各一组，按衣服调 | 每个对象一组，胸按衣服选预设 |

差别归纳：

1. DOA6 把胸当成会变形的肉，另外两家都当骨头。
2. DOA6 的布料网格和看得见的布分开（插值 + 厚度），另外两家是骨头直接蒙皮。
3. DOA5LR 的网格布弹簧最全，我们 44b174e 只加了横向连杆。
4. 两个 DOA 都是"每块东西各自列碰撞体"，我们是一套通用的。
5. 两个 DOA 的参数都是按衣服调的，我们按类别。

## 4. 可插拔的设计（`Runtime/RoeCloth.cs`）

- **类别**：胸 `breast`、身体（臀、大腿的肉）`body`、头发 `hair`、裙子（所有布片）`skirt`、飘带 `ribbon`、链子和硬饰物 `chain`。
  ROE 角色按骨头名字分类。霞的骨头名字只是编号，按她的物理数据分类（`RoeDoaRig.KindsOf`）。
- **解算器**（`RoeClothSolvers`）：

  | 名字 | 是什么 | 能做哪些类别 |
  |---|---|---|
  | `bone` | 我们的骨骼布料，照 Magica Cloth 2 的做法（10-03） | 全部 |
  | `bone_legacy` | 10-02 的骨骼布料 | 全部 |
  | `doa6` | DOA6 自己的系统，用角色的游戏数据（`RoeDoaPhysics`） | 只有带 DOA6 数据的角色、只有数据里有的类别 |
  | `doa5lr` | 同样的骨链，约束换成 DOA5LR 的弹簧网（`RoeBoneCloth.Doa5.cs`，10-04 晚，第 11 节） | 全部（胸在方案里交给骨骼布料） |
  | `magica` | Magica Cloth 2 本身（`RoeMagicaCloth`，10-04 装上） | 全部，但 DOA6 角色的胸（软体）交给骨骼布料；要装上插件（插件自己加编译符号 `MAGICACLOTH2`） |

  解算器只是一个实现了 `IRoeCloth` 的类，只模拟交给它的类别，再用 `covers` 说明在某个角色身上能做哪些。
  再加一个（别的引擎、别的游戏的系统），就是在列表里加一项。
- **方案**（`RoeClothBackends`，F4 依次切换）：

  | 方案 | 怎么分 |
  |---|---|
  | `auto`（默认） | 每人用自己游戏的：带 DOA6 数据的角色用 `doa6`，其他用 `magica_style` |
  | `magica_style` | 全部用骨骼布料 |
  | `doa6` | 全部用 DOA6 的（做不了的类别交给骨骼布料） |
  | `doa6_breasts` | 胸和身体用 DOA6 的软体，其余用骨骼布料（一次只比一类） |
  | `doa5lr_style` | 裙子、头发、飘带、链子用 DOA5LR 式弹簧网，胸用骨骼布料（DOA5LR 的胸是预设表驱动，不模拟） |
  | `legacy` | 10-02 的骨骼布料 |
  | `off` | 不模拟 |
  | `magica` | 全部用 Magica Cloth 2（装上插件后才有） |

  一个角色身上用到几个解算器，就由 `RoeClothRouter` 把它们合在一起（每步依次跑）。
- **Magica Cloth 2（10-04 晚装上，`docs/magica-cloth-2.md` 第 10 节）**：
  - 插件在 `Assets/MagicaCloth2`（不进仓库），它自己往 `ProjectSettings.asset` 加编译符号 `MAGICACLOTH2`（这个文件不提交），F4 里就多出 `magica` 方案。
  - ROE 角色里爆衣拆出来的布片（a08 的长裙片和后腰垂片、g04 的前片、左飘带、后片）用 MeshCloth 直接模拟网格，其余骨链用 BoneCloth；
    霞的网格布用 BoneCloth 模拟控制点（成环的连成 Sequential Loop Mesh），看得见的布照旧从控制点重建。
  - 想只让它接管某几类，比如裙子和头发，在 `RoeClothBackends.All` 里加一行：
    `new Backend { name = "magica_skirts", fallback = "bone", byKind = { { "skirt", "magica" }, { "hair", "magica" } } }`。
  - Magica 只在播放模式里跑：批处理里手动推进的探针和录像看不到它，用播放模式录像 `RoeClothPlayDemo` 录、量。
- **10-04 顺手修的老毛病**：F4 以前只改了屏幕上的提示，实际一直用骨骼布料（从 44b174e 起）。
  - 原因：场景存盘时，没设的 `FighterRig.clothBackend` 存成了空字符串，`clothBackend ?? ClothBackend` 永远取到空字符串，退回第一项。
  - 现在空字符串也当没设。

## 5. 霞是怎么接进来的

## 6. DOA6 的物理在这里怎么跑（`Runtime/RoeDoaPhysics.cs`）

每步 1/60 秒拆成 2 个子步（120 Hz），在姿势算完之后跑。

- **骨链**（飘带、绳、马尾）：
  - 质点跟着第一根骨走；
  - 速度每 1/60 秒保留 p2；
  - 重力 × p0；
  - 往动画位置拉回 p8（每 1/60 秒）；
  - 迭代 p7 次保持骨长，碰自己那几组碰撞体，摩擦 p9；
  - 每根骨转向下一个质点。
- **摆动骨**（刘海）：同一套，每缕两根，每根不超出 f0–f3 里最大的角度。
- **软体**：
  - 每个格点算出蒙皮目标，钉住的点直接放在目标上；
  - 其余的点被弹簧拉向目标：加速度 = 刚度 ×（目标 − 位置）− 阻尼 ×（速度 − 目标的速度）+ 重力的变化量；
  - 格子的边（系数 0.88）、面对角线（0.55）保持长度，壳保持体积（0.4）。
    长度和体积取目标当前的形状，不取绑定姿势的（10-04 晚改的，见第 10 节"调的过程"第 6 条）；
  - 碰手臂、手、大腿；
  - 每个点离目标不超过每轴 10/16/8 厘米；
  - 最后每个点按 `w_self` 显示自己的晃动。
- **565/566**：按格点插值摆放；下一帧动画之前放回原位。
- **辅助骨**：`RoeDoaRig.DriveHelpers`，在 `FighterRig` 里跟在 ROE 角色的辅助骨后面，不管用哪个物理方案都跑，所以手臂、腿的皮肤在 `off` 里也一样。
  - 扭转链 00、01、02 分到肢体自身扭转的 0、一半、全部（猜：常见的分法）；
  - `*NoTwist` 一点不分。
- 霞的动作片段从不给这些骨头打关键帧，所以游戏动作里也一直模拟（`FighterRig.clothOverGameClips`）。

**哪些是猜的，以及可调的量**（都是 `RoeDoaPhysics` 的静态字段，默认 1）：

| 量 | 现在的读法 | 调它的开关 |
|---|---|---|
| 软体刚度 270 | 加速度 = 270 ×（目标 − 位置），即 2.6 Hz | `SoftSpring` |
| 软体阻尼 0.75 | 每 1/60 秒保留 75% 的相对速度（阻尼比约 0.53），和骨链的阻尼参数同一种读法 | `SoftDampingRatio` |
| 软体重力 −6 | 只加"姿势变化带来的那部分"：站直时为 0，弯腰往脸那边、侧躺往侧面 | `SoftGravity` |
| 每轴 10/16/8 | 厘米，节点离目标的上限（她自己的左右、上下、前后） | — |
| `w_self` | 节点显示出多少自己的晃动 | — |
| 骨链 p2 / p8 / p0 | 每 1/60 秒保留的速度 / 拉回动画的比例 / 重力倍数 | `ChainRestore`、`ChainGravity` |
| 网格的混合值 | 1 − (1 − 游戏的值)²，接缝处更贴身体 | `DoaPhysicsBuilder.SeamEase`（1 = 游戏的原值；改了要重建预制体） |
| 格子的静止形状 | 目标当前的形状（蒙皮弯了它跟着弯） | `SoftRestFromPose`（false = 绑定姿势的边长和体积，10-04 白天的做法） |
| 碰撞 | 动画姿势本身陷进碰撞体的深度算允许的，只挡比动画更深的（和骨骼布料一样） | `SoftColliders`（只给检查用） |
| 瞬移 | 一步动了 0.5 米以上就从姿势重新开始 | `Teleport` |

## 7. 调的过程：每个问题和数字

`DoaPhysicsProbe.Soft` 照演示的脚本走一遍（站架、前进、后退、两边侧步、A C D B），在指定的步数列出离目标最远的格点：
偏多少（她自己的坐标）、挂在哪些骨上、目标在哪个碰撞体里、它的弹簧被拉长多少；全部空闲格点的平均偏离和平均方向；
最后报告每个碰撞体推了几次、最远推多少，顶到每轴上限多少次。

1. **第一次构建就崩了**：`doa6_physics.py` 把每个顶点的 8 个格点编号和权重当成了 1 个（源数据是平铺的数组，8 个一组）。
2. **F4 不切换**：见第 4 节最后。
3. **胸往下坠 2–4 厘米、变形**：重力整个加在已经是"受重力后"形状的目标上。6 / 270 = 2.2 厘米的下垂，再被格子约束拉变形。
   现在只加重力方向相对静止姿势的变化（站直时 0）。
4. **走路时胸被拖在后面 4–8 厘米**：阻尼用的是世界速度，等于给胸加了空气阻力。现在按相对目标的速度阻尼，两个子步之间对目标插值。
   前进时偏得最远的点从 6 降到 3 厘米。
5. **565/566 的反馈**：几个格点的目标挂在这两根骨上，而它们又按格点摆放，动画不复位它们。现在每帧动画前放回原位（数字没变，属于正确性）。
6. **站架里胸壁边被手臂带走**：每边 24 个钉住点里有 15 个部分挂在上臂的扭转辅助骨 `RF_*_Arm_*` 上（8 个权重在 0.3 以上），
   这几根在我们的骨架里 100% 跟着上臂扭。
   加了扭转辅助骨之后：
   - 站架里偏得最远的点从 3.8 降到 1.5 厘米；
   - 每步最大偏离的平均从 5.7 降到 4.2 厘米；
   - 顶到上限的次数减半（4436 → 2452）。
7. **手臂把胸挤成尖的、胸衣下面裂开**：站架里上臂贴着胸的侧面，格子比皮肤大一圈（最多一格，3 厘米），格点被推到胶囊外面。
   现在动画本身陷进去的深度算允许的。
8. **侧踢起手把胸甩起 10 厘米**：关掉碰撞数字不变，是惯性。从站架切到踢腿，胸口 0.1 秒里移动十几厘米。
   阻尼从"1 − 阻尼比"（0.25）改成"每 1/60 秒保留的速度"之后，平均偏离：
   - 走路 1.3–2.9 → 0.7–2.1 厘米；
   - 侧踢 7.8–10.9 → 6.1–9.0 厘米。
9. **罩杯下缘和胸衣之间的缝**：胸衣中缝不在软体里，罩杯下缘以上 2–4 厘米就有混合值 0–0.1 的顶点（几乎全跟软体）。

- 另外两边臀部各有一块 528 个格点的"身体"软体（标志 0x80），胸是每边 211 个格点（刚度 400、阻尼 0.83、重力 −4）。

### 重建公式（游戏的，ripper_tpose `docs/doa-clothing-and-cloth.md`）

```
u_k = Σ_j w_h[j]·CP[k][j]     v_k = Σ_j dw_h[j]·CP[k][j]          （k：4 行，j：每行 4 个点）
a = Σ_k w_v[k]·u_k     b = Σ_k dw_v[k]·u_k     c = Σ_k w_v[k]·v_k     d = b × c（不归一化）
位置 = a + d·厚度     法线 = normalize(c·n.x + b·n.y + d·n.z)     切线同理（w 是手性）
```

搬到 Unity 要改三处：

1. **镜像**：霞的模型是游戏的 X 镜像，镜像会把叉积翻过来，所以 d = c × b，切线的手性取反。
2. **单位**：游戏是厘米。换成米以后 b、c 是原来的 1/100，d = b × c 是 1/10000，所以乘 d 的量都要 × 100：
   厚度，以及法线、切线里 d 的系数。第一次只给厚度乘了，位置全对，法线平均偏 50–60°。
3. **切线**：不用游戏的系数，改成静止时按导入网格的切线，在同一个 (c, b, d) 坐标系里反解出三个系数。
   身体其它部分的法线贴图是按 Unity 自己算的切线读的（MikkTSpace，翻过的 UV），游戏的切线是另一套，差最多 160°。

### 在预制体上怎么搭（`DoaPhysicsBuilder`）

- 每个控制点建成一个节点 `<父骨>_grid<块>_r<行>c<列>`：第 0 行挂在父骨上，第 r 行挂在第 r − 1 行下面。
  这样每一列就是一条从父骨垂下来的链，骨骼布料也能把它当裙链甩（`RoeDoaRig.KindsOf` 把第 2 行以下标成 skirt）。
- 导入的布网格留着、不显示（腰带靠它的蒙皮），旁边另建一个普通 MeshRenderer 画重建出来的网格（`meshes/<网格>_cloth.asset`）。
- 每个 Unity 顶点按位置 + UV 对上游戏的顶点，全部对上，最大误差 0.01 毫米。结果写成二进制绑定文件 `meshes/<网格>_cloth.bytes`：
  每个顶点是刚性还是重建，16 个控制点、16 个权重、厚度、系数。
- 双面的荷叶边有"孪生"顶点：位置、UV 都一样，法线相反。只按位置 + UV 对，两个会对到同一个游戏顶点，裙子有 198 个顶点法线反了。
  现在位置、UV 一样时再比法线（裙子分开了 214 对）。
- `DoaFighter.CheckSurfaces`（每次 `DoaFighter.Stills` 都跑）在静止时重建一次，和导入的网格逐顶点比。
  现在 4 块布：位置 ≤ 0.01 毫米，法线 ≤ 0.2°，切线 0°，没有翻的。
- `DoaFighter.Build` 只在导入设置变了时才重新导入 FBX：1373 根骨的模型导入要 5–9 分钟，只改物理时不用等。

### 每一帧

1. `RoeDoaRig.DriveGrids`：最上面两行按蒙皮放到骨头上，跟着臀和大腿走。和扭转辅助骨一样，任何物理方案都跑。
   `FighterRig` 的"挂在臀上的裙片"规则（裙片按臀的朝向保持站架里的角度）不再管这些控制点。
2. 物理方案移动其余的控制点：
   - `doa6`：下面的网格布解算器；
   - `magica_style`：骨骼布料把每一列当一条链甩；
   - `off`：下面各行跟着第 1 行平移，不动。
3. `RoeDoaRig.RebuildSurfaces`：按公式重建看得见的布，每帧约 8700 个顶点。

### DOA6 的网格布解算器（`RoeDoaPhysics.GridSim`）

参数字的读法都是猜的：

- 每 1/60 秒拆成 2 个子步，顶上两行在两步之间按直线插值。
- 其余的点：Verlet，速度每 1/60 秒保留 1 − 字 5（0.95），重力 9.8。
- 往静止形状（挂在父骨上的样子）拉回：每 1/60 秒拉回字 6 那么多（裙子 0.2，袖子、胸前片 0.7），和骨链的字 8 同一种读法。
  泡泡袖、胸前片要保持形状，所以大；裙子要飘，所以小。
- 约束迭代次数 = 字 37 各字节之和，限制在 3–8 次：
  - 格子的连线（刚度 1）；
  - 格子的对角（字 7，0.7）；
  - 隔一个点（字 8：裙子 0.1，袖子 0.5）；
  - 每列不比静止时长 5% 以上。
- 碰自己那组碰撞体：动画姿势本身陷进去的深度算允许的。也碰地面。碰到的点每个子步受一次摩擦（字 12，0.8）。

## 11. DOA5LR 式弹簧网（`doa5lr_style`，10-04 晚）

用户 10-04 要求调研 DOA5LR，"看物理系统是否有其他差别，最好做成可插拔的设计"。调研做完后，这里把它最有特点的部分做成一个可以切换的方案：
网格布的弹簧网。

### 数据（`KASUMI_COS_004` 的裙子、她的绳和飘带、`KASUMI_HAIR_001`）

- 一个质点就是一根骨头。弹簧有五类：

  | 类 | 连什么 | 裙子（`WGT_acs_skt`，14 列、134 个质点、850 根弹簧）的两个刚度 |
  |---|---|---|
  | 竖向（structural） | 同一列相邻的点 | (1, 2) 120 根，(1, 1.5) 5，(0.5, 1) 1 |
  | 横向（horizontal） | 相邻两列同一行 | (1, 2) 100，(0.5, 1) 92，(1, 1.5) 16 |
  | 斜拉（shear） | 格子的对角 | (0.5, 1) 219，(1, 1.5) 129，(1, 2) 32 |
  | 隔一个（bend） | 同一列隔一个点 | (0.5, 1) 99，(1, 1.5) 5 |
  | 远程（long range） | 列根到第 2–7 行 | (0.5, 1) 31，(1, 1.5) 1 |

- 每根弹簧还有静止长度、两端各挪多少（核实：0.5 / 0.5，从固定的根出发的是 0 / 1）。
- 两个刚度：裙子上第二个总是第一个的 1.5–2 倍；绳和头发竖向 (10, 10)、隔一个 (1, 1)；泡泡袖有 (2, 1)。
  读成"比静止短时的刚度、比静止长时的刚度"（猜）：布容易折、不容易拉长，泡泡袖不容易被压扁。
- 每个对象 4 个字 p2–p5，每个质点 5 个字 a–e。
  - 头发的质点字 b 从根部起是 1、1、1、0.5、0：这就是第 2 节说的"根部按住"。
  - 其余的含义都是猜的。

| | p3 | p4 | p5 | 质点 b |
|---|---|---|---|---|
| 裙子 | 0.8 | 0.5 | 0.11 | 0 |
| 头发 | 0.5 | 0.43 | 0.04 | 1, 1, 1, 0.5, 0… |
| 绳、飘带 | 0.4–1.0 | 0.1–0.2 | 0.03–0.12 | 0 或 0.5 |

### 读法和做法（`Runtime/RoeBoneCloth.Doa5.cs`）

- 用骨骼布料现成的骨链、链之间的横向连接、腿和臀的胶囊、地面，只把约束换掉：
  - 骨骼布料（`magica_style`）靠 Magica 的"角度复原 + 角度限制"保形；
  - 这里靠 DOA5LR 的弹簧网。

  所以对比视频里两边的差别就是约束系统的差别。
- 弹簧网从骨链和横向连接搭出来：横向（已有的连接）、斜拉（连接两端各和对方的下一个点）、竖向隔一个、横向隔一个（一个点左右两个邻居之间）、
  远程（每个点到本链根部，只管不被拉长）。竖向相邻靠骨头长度，本来就是硬的。
- 每个子步（120 Hz）：
  1. Verlet；相对动画的那部分速度每 1/60 秒丢掉 p4（读成阻尼）；重力 9.8 × p3。
  2. 往动画姿势拉 p5（每 1/60 秒）。头发按根部比例按住（`b` = 1 的点直接放在动画位置上）。
  3. 迭代：每根弹簧按长了还是短了取对应的刚度。字 k 换成每次迭代的比例 1 − e^(−k/2)：k = 10 约 0.99，2 约 0.63，1 约 0.39，0.5 约 0.22。
     之后是骨头长度、角度限制、碰撞体、地面。
- 不用骨骼布料的"惯性分成"：阻尼是相对动画速度的，布本来就跟着身体走，只有绕着动画姿势的晃动会衰减。
- 胸：DOA5LR 不模拟（预设表驱动），这个方案里胸交给骨骼布料。

可调（`RoeBoneCloth` 的静态字段）：

| 量 | 默认 |
|---|---|
| `Doa5K` 刚度换算 1 − e^(−k / Doa5K) | 2 |
| `Doa5Damping`、`Doa5Pull`、`Doa5Gravity` × p4、p5、p3 | 1 |
| `Doa5LongRange` 远程弹簧 | 开 |
| `Doa5AngleLimit` 保留骨骼布料的角度限制 | 开 |

### 顺带：DOA6 网格布在骨骼方案里连成一片

- 以前霞的海盗裙在骨骼布料里是 20 条各自独立的链：每列挂在自己的第 1 行控制点上，算不成同一组；
  看得见的布是重建的、没蒙皮到控制点上，按皮肤三角形找连接也找不到。

2. **加上角度限制之后**（链尖均方根 / 最大，度）：
